# Демо-режим для жюри

25-минутную сессию на защите не дождаться, поэтому есть **ускоренные комнаты**.

## Как включить
Только оператор сервера, переменной окружения: `TOMATO_DEMO=1 npm start` (или `npm run start:demo`).
Без неё `POST /api/rooms {"demo":true}` → `403 DEMO_DISABLED`, а поля `focusSeconds/breakSeconds` игнорируются.
`GET /api/health` отдаёт `demoMode`, а комнаты — `room.demo`, чтобы интерфейс мог показать плашку.

```bash
TOMATO_DEMO=1 npm start
POST /api/rooms {"name":"Демо","demo":true,"focusSeconds":25,"breakSeconds":15}
```
Границы: `focusSeconds` 5–600, `breakSeconds` 5–300.

## Что НЕ меняется (важно для защиты)
* Тот же код: фазы определяются теми же метками времени, награда выдаётся той же `completeSession`
  с теми же проверками (досрочный выход, потеря связи > grace, мульти-сессии, идемпотентность).
* Клиент не может ускорить время: длительность хранится в комнате, а не присылается при старте.
* Обычные комнаты в демо-режиме остаются обычными (10–120 минут).
* В демо-комнатах награда считается как за стандартные 25 минут (иначе демо нечего показывать);
  суточный потолок в демо-режиме поднят до 500. На production переменная не выставляется — ускоренных
  комнат и этих исключений там не существует.

## Тесты
Автотесты не используют ни демо, ни системное время: `FakeClock` двигает часы детерминированно
(`tests/helpers.js`). Системное время компьютера не меняется.

## Сквозной сценарий
`npm run demo` (против сервера с `TOMATO_DEMO=1`): три игрока, досрочный выход, награды, помощь, пакости,
попытки читов, три цикла, командная победа. Параметры: `FOCUS=25 BREAK=15 API=http://localhost:8787`.
