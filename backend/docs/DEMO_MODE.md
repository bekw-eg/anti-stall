# Демо-режим для жюри

25-минутную сессию на защите не дождаться, поэтому есть **ускоренные комнаты**. Чтобы ускоренное время
не стало способом обойти правила наград, демо-комнаты работают в **песочнице**: в них играют только
песочные (демо) аккаунты, а их прогресс не существует на сервере без демо-режима.

## Как включить
Только оператор сервера, при запуске:

```bash
npm run start:demo                 # = node --disable-warning=ExperimentalWarning src/server.js --demo
node src/server.js --demo          # флаг --demo работает и в Windows cmd/PowerShell
TOMATO_DEMO=1 npm start            # то же через переменную окружения (bash)
```

* Если `TOMATO_DB` не задан, демо-сервер пишет в **отдельный файл** `data/tomato-demo.db` (а не в `data/tomato.db`).
  При старте в лог выводятся путь к БД и предупреждение о демо-режиме.
* `GET /api/health` отдаёт `demoMode`, комнаты — `room.demo`, профиль — `sandbox`, чтобы интерфейс мог показать плашку.

## Песочница: правила (проверяет сервер)
| Действие | Без демо-режима | В демо-режиме |
|---|---|---|
| `POST /api/users {"name","sandbox":true}` | `403 DEMO_DISABLED` | 201, `user.sandbox = true` |
| Токен песочного аккаунта | не авторизуется: REST `401 UNAUTHORIZED`, WS `error UNAUTHORIZED` + закрытие 4401 | работает |
| Песочный аккаунт: создать/войти в обычную комнату | — | `403 SANDBOX_DEMO_ONLY` |
| Обычный аккаунт: создать/войти в демо-комнату | `403 DEMO_DISABLED` (создание) | `403 DEMO_SANDBOX_ONLY` |
| Запуск фокуса в демо-комнате | `403 DEMO_DISABLED` (комната из старой БД) | разрешён хосту-песочнице |

* Поле `sandbox` — только boolean (иначе `400 INVALID_FIELD`); через `PATCH /api/users/me` его не изменить.
* Проверка песочницы стоит во всех путях входа: `POST /api/rooms`, `POST /api/rooms/join {code}`, `POST /api/rooms/:id/join`
  (в том числе повторный вход после выхода).
* Тип комнаты фиксируется при создании: `PATCH /api/rooms/:id/settings {"demo":…}` обычным хостом с `true` → `403 DEMO_SANDBOX_ONLY`,
  песочным с `false` → `403 SANDBOX_DEMO_ONLY`; другой тип (возможен только в старых данных) → `400 INVALID_FIELD`.
* Старые данные (обычный игрок, оказавшийся в демо-комнате до появления песочницы): при старте фокуса он пропускается
  с причиной `sandbox_mismatch` в `start.skipped[]`, а хост-«чужак» получает `403 DEMO_SANDBOX_ONLY`.
* Миграция аддитивная: колонка `users.sandbox INTEGER NOT NULL DEFAULT 0` (схема v4), все существующие пользователи — обычные.

## Создание демо-комнаты
```
POST /api/users {"name":"Лотти","sandbox":true}            → token
POST /api/rooms {"name":"Демо","demo":true,"focusSeconds":25,"breakSeconds":15}
```
Границы: `focusSeconds` 5–600, `breakSeconds` 5–300.

## Что НЕ меняется (важно для защиты)
* Тот же код: фазы определяются теми же метками времени, награда выдаётся той же `completeSession`
  с теми же проверками (досрочный выход, потеря связи > grace, мульти-сессии, идемпотентность).
* Клиент не может ускорить время: длительность хранится в комнате, а не присылается при старте.
* Обычные комнаты на демо-сервере ведут себя **как на production**: 10–120 минут, обычные потолки и кулдауны.
* Исключения действуют **только в демо-комнатах** (по `room.demo`), а не глобально:

| Правило | Обычная комната | Демо-комната | Ключ конфигурации |
|---|---|---|---|
| Награда за сессию | масштаб по длительности (0.4–2 от 25 минут) | как за стандартные 25 минут | — |
| Суточный потолок награждённых сессий | 16 | 500 | `economy.dailyRewardedSessions` / `economy.demoDailyRewardedSessions` |
| Суточный потолок наград Tower Defense (раунды и, отдельно, дуэли) | 8 | 500 | `economy.td.dailyRewardedRounds` / `economy.td.demoDailyRewardedRounds` |
| Кулдаун пакостей | 20 с | 1 с | `social.prank.cooldownMs` / `social.prank.demoCooldownMs` |

Поскольку в демо-комнатах играют только песочные аккаунты, эти исключения не дают прогресса обычным игрокам.

## Скрипты для показа (против живого демо-сервера)
Все принимают `--api URL` (или переменную `API`), по умолчанию `http://localhost:8787`.

* `npm run demo:seed` — 4 песочных аккаунта (Лотти, Аня, Борис, Вика) и демо-комната «фокус 25 с / перерыв 15 с»
  с хостом Лотти; токены, id и код комнаты сохраняются в `data/demo-seed.json` (в `.gitignore`) и печатаются таблицей.
  Если сервер не в демо-режиме — понятная ошибка и код выхода 1.
* `npm run demo:bots -- --room CODE [--bots 2]` — песочные боты входят в комнату по коду, ставят личные задачи,
  держат присутствие (WS `heartbeat` каждые 5 с, как клиент), отмечают готовность в `waiting` и печатают фазы.
  Команды из stdin: `leave <бот>` (досрочный выход из фокуса), `help <цель> [boost|shield]`, `prank <цель> [fog|sticker]`,
  `status`, `quit` (боты выходят из комнаты).
* `npm run cheat-check` — сам создаёт песочных игроков, демо-комнаты (фокус 5 с) и обычный аккаунт, выполняет атаки
  и печатает таблицу «Атака | Ожидание | Факт | Итог»; код выхода 1, если хоть одна атака прошла.
  Те же атаки детерминированно проверяет `tests/security.test.js`.
* `npm run demo` — сквозной сценарий: три песочных игрока, досрочный выход, награды, помощь, пакости, попытки читов
  (включая вход обычного аккаунта в демо-комнату), три цикла, командная победа. Параметры: `FOCUS=25 BREAK=15`.

## Тесты
Автотесты не используют системное время: `FakeClock` двигает часы детерминированно (`tests/helpers.js`).
Правила песочницы — `tests/sandbox.test.js`, атаки — `tests/security.test.js`.
