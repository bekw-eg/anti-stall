# Голосовой чат

Голос — постоянный «коворкинг-фон» комнаты: можно говорить на перерыве и просто слышать друг друга в фокусе.
Он **не обязателен**: таймер, награды и игра работают одинаково, вошёл человек в голос или нет. В голос входят кнопкой
«Войти в голос» в нижней полосе.

## Как устроено

```
Браузер A ──WebSocket /ws── сервер Tomato ──WebSocket /ws── Браузер B
    │        voice_join / voice_signal (SDP, ICE)                │
    └──────────────── звук (WebRTC, SRTP) ───────────────────────┘
                 напрямую или через TURN, если сеть не пускает
```

* **Сигналинг** идёт по уже открытому WebSocket комнаты (`voice_join`, `voice_signal`, `voice_state`, `voice_leave`, см. API.md).
  Сервер не видит и не хранит звук: он только пересылает SDP/ICE участникам того же голосового канала.
* **Топология — mesh** (каждый с каждым), до 8 человек в канале (`TOMATO_VOICE_MAX_PEERS`). Для учебной комнаты
  на 3–6 человек это проще и дешевле медиасервера: у каждого N−1 исходящих потоков Opus по ~30–40 кбит/с.
* **Кто звонит.** Вошедший позже отправляет offer всем, кто уже в канале. Одновременные offer (например, после
  переподключения) разруливает схема *perfect negotiation*: «вежливая» сторона уступает.
* **ICE-кандидаты, пришедшие раньше SDP, не теряются**: клиент копит их и применяет после `setRemoteDescription`;
  сигналы от одного собеседника обрабатываются строго по очереди.
* **Состояние канала** живёт в памяти сервера (это присутствие, а не данные): один пользователь — одно место.
  Повторный вход с другой вкладки вытесняет старое соединение (`voice_kicked {reason:"replaced"}`), обрыв сокета
  или выход из комнаты убирает игрока из голоса — у остальных не остаётся «мёртвых» участников.

## Поведение клиента (`frontend/src/tomato/voice`)

| Ситуация | Что происходит |
|---|---|
| Mute | трек микрофона выключается (`track.enabled = false`), остальные видят значок |
| Deafen | все входящие `<audio>` глушатся и микрофон выключается; включение микрофона снимает deafen |
| Индикатор «говорит» | громкость микрофона (WebAudio) каждые 50 мс, огибающая с плавным спадом, гаснет после 0,8 с тишины; рассылается только при изменении |
| Нет доступа к микрофону | вход слушателем (`recvonly`): слышно всех, статус «нет доступа к микрофону»; кнопка микрофона повторно запрашивает разрешение и без перезахода подключает микрофон |
| Обрыв WebSocket | WebRTC-соединения закрываются, после переподключения сокета клиент сам возвращается в канал |
| Сбой сети у WebRTC | `failed` → `restartIce()`; `disconnected` дольше 3 с → `restartIce()` |
| Выход / закрытие комнаты / вкладки | соединения закрываются, микрофон освобождается, сервер рассылает `voice_peer_left` |
| Страница по HTTP (не localhost) | браузер не даёт микрофон — кнопка неактивна с подсказкой «Голос доступен только по HTTPS» |

## STUN / TURN — работа в разных сетях

По умолчанию сервер выдаёт публичные STUN (`stun.l.google.com`, `stun.cloudflare.com`). Этого хватает в большинстве
домашних и мобильных сетей. За строгим NAT (университетский Wi-Fi, корпоративные сети) прямое соединение невозможно —
нужен **TURN**, который ретранслирует звук.

| Переменная | Назначение |
|---|---|
| `TOMATO_STUN_URLS` | список через запятую, напр. `stun:stun.l.google.com:19302` |
| `TOMATO_TURN_URLS` | напр. `turn:turn.example.com:3478?transport=udp,turns:turn.example.com:5349` |
| `TOMATO_TURN_SECRET` | общий секрет coturn (`use-auth-secret`) — **рекомендуется** |
| `TOMATO_TURN_USERNAME` / `TOMATO_TURN_CREDENTIAL` | статичные логин/пароль (если секрета нет) |

С общим секретом сервер выдаёт каждому временный логин на час: `username = "<unix-время истечения>:<userId>"`,
`credential = base64(HMAC-SHA1(secret, username))` — стандарт REST API coturn. Секрет на клиент не уходит.

Минимальный coturn (на той же ВМ, порты 3478/udp+tcp и 49152–65535/udp открыты):

```bash
docker run -d --network host --name coturn coturn/coturn \
  -n --listening-port=3478 --fingerprint --use-auth-secret \
  --static-auth-secret="$TURN_SECRET" --realm=antistall --external-ip="$PUBLIC_IP"
TOMATO_TURN_URLS="turn:$PUBLIC_IP:3478?transport=udp,turn:$PUBLIC_IP:3478?transport=tcp" \
TOMATO_TURN_SECRET="$TURN_SECRET" npm start
```

`GET /api/config` отдаёт `voice.turnConfigured`, а `voice_joined` — `relay: true|false`.

## Проверка

* `backend/tests/voice.test.js` — сигналинг: доступ, пересылка только своему каналу, очистка полей, mute/deafen/speaking,
  обрыв, вытеснение второй вкладкой, выход из комнаты, лимит канала, пачки ICE-кандидатов, TURN-логины.
* `frontend/src/tomato/voice/VoiceClient.test.ts` — WebRTC-логика на имитации сети: 3 участника каждый-с-каждым,
  коллизия offer, кандидаты до SDP, слушатель без микрофона, mute/deafen, индикатор, выход, переподключение, ICE restart.
* `e2e/voice.e2e.mjs` — **настоящий Google Chrome**, 4 участника + слушатель без доступа к микрофону: соединения
  `connected`, растущие RTP-пакеты (`getStats`), индикатор говорящего, mute/deafen у других, выход, перезагрузка
  страницы без «мёртвых» соединений. Подменяется только источник звука (тестовый микрофон Chrome).
