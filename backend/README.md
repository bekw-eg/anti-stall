# Tomato backend

Серверная часть «Tomato — коллективная боталка с геймификацией». Весь игровой процесс
(комнаты, таймер, сессии, XP, монеты, улучшения, достижения, командное испытание, помощь и пакости,
защита от накрутки) живёт здесь. Frontend — только отображение, его можно заменить целиком.

## Технологии

| Что | Выбор | Почему |
|---|---|---|
| Среда | Node.js ≥ 22.13 (проверено на 24.13) | ESM, без сборки |
| HTTP | встроенный `node:http` + маленький роутер | без зависимостей |
| Realtime | `ws` (единственная зависимость) | в Node нет серверного WebSocket |
| БД | встроенный `node:sqlite` (WAL) | нет нативных зависимостей, транзакции, UNIQUE/partial-индексы |
| Тесты | встроенный `node:test` | без зависимостей |

> `node:sqlite` в Node 22–24 помечен experimental (предупреждение глушится флагом в npm-скриптах).

## Запуск

```bash
cd backend
npm install
npm start                 # http://localhost:8787, WebSocket /ws, БД data/tomato.db
npm run start:demo        # демо-сервер: песочные аккаунты, ускоренные комнаты, отдельная БД data/tomato-demo.db (docs/DEMO_MODE.md)
npm test                  # 125 автотестов, управляемые часы
npm run demo              # сквозной сценарий для жюри (нужен демо-сервер)
npm run demo:seed         # изолированные тестовые аккаунты и комната -> data/demo-seed.json
npm run demo:bots -- --room CODE   # боты-игроки для показа (команды leave/help/prank/status/quit)
npm run cheat-check       # атаки на живой демо-сервер, таблица PASS/FAIL
```

Переменные окружения: `PORT` (8787), `HOST`, `TOMATO_DB` (путь к файлу SQLite),
`TOMATO_DEMO=1` (или флаг `--demo`), `TOMATO_STATIC_DIR` (раздавать собранный frontend), `TOMATO_CORS_ORIGIN` (по умолчанию `*`); голос — `TOMATO_STUN_URLS`, `TOMATO_TURN_URLS`,
`TOMATO_TURN_SECRET` (см. docs/VOICE.md).

Frontend в dev-режиме проксирует `/api` и `/ws` на `http://localhost:8787` (`frontend/vite.config.ts`,
адрес переопределяется `VITE_BACKEND_URL`). Для отдельного хоста: `new TomatoClient({ baseUrl })`.

## Архитектура

* **Сервер — единственный источник истины.** Клиент может только вызывать допустимые REST-действия
  (`start`, `abort`, `help`, `purchase`…). Маршрутов вида «выдай награду/заверши сессию» нет; по WebSocket
  клиент вправе лишь `auth/subscribe/unsubscribe/heartbeat/ping`, остальное → `UNKNOWN_EVENT`.
* **Таймер по меткам времени.** В БД лежат `phase`, `phase_started_at`, `phase_ends_at`, `cycle_id`.
  Планировщик (500 мс) переводит фазы, но корректность от него не зависит: каждый запрос и подписка
  «догоняют» комнату по `clock.now()`. Таймер не зависит от браузера и переживает перезапуск процесса.
* **Награды идемпотентны.** `reward_transactions` с `UNIQUE(user_id, key)`; ключи: `focus:<sessionId>`,
  `ach:<id>`, `challenge:<room>:<team>`, `upgrade:<id>:<level>`. Повтор ключа — no-op.
* **Мульти-сессии невозможны.** Частичный UNIQUE-индекс `focus_sessions(user_id) WHERE status='active'`.
* **Деньги не уходят в минус.** `UPDATE … WHERE coins >= ?` + `CHECK(coins >= 0)`; покупка принимает
  `expectedLevel` (оптимистичная блокировка против двойных кликов/гонок).
* **Транзакции и события.** Мутации выполняются в `BEGIN IMMEDIATE`; события WebSocket уходят только
  после `COMMIT` и отбрасываются при откате.
* **Единый процесс.** `node:sqlite` синхронный, поэтому обработчики внутри процесса не перемежаются, а
  инварианты дополнительно закреплены в схеме. Масштабирование на несколько процессов потребует
  внешней шины для WebSocket-рассылки (см. «Ограничения» в docs/REPORT.md).

## Игровые правила (по умолчанию, `src/config.js`)

* Сессия 25 мин / отдых 5 мин (10–120 / 3–30). Награда за 25-минутную сессию: **+100 XP, +20 Tomato Coins,
  +1 очко команды**; для других длительностей масштабируется (коэффициент 0.4–2).
* Награду получает только тот, чья сессия дошла до конца: не нажал «досрочно», не пропал дольше
  `graceMs` (30 с без heartbeat), успел войти до старта. Потолок: 16 награждаемых сессий за 24 ч.
* Уровень *n* наступает при `50·n·(n−1)` XP (2 → 100, 3 → 300, 4 → 600…).
* Улучшения (за монеты, открываются уровнем): «Крепкие стены» (+25 HP базы), «Усиленные башни»
  (+10% урона), «Командная аура» (усиливает ваш «Бонус»). Покупка недоступна во время Focus.
* Командное испытание «Марш к крепости экзамена»: 4 узла Road Map, цель — 6 очков; каждая награждённая
  фокус-сессия = +1. За каждый промежуточный этап («Лес знаний» — 2 очка, «Мост дедлайнов» — 4) участники с вкладом
  получают +25 XP / +10 монет; при достижении цели — +150 XP / +60 монет (всё один раз, проверяет сервер).
* Командный режим Team A/B (`teamMode:true`): две команды идут по одной карте, побеждает первая набравшая цель (ничья — награда обеим).
* **Tower Defense на перерывах** (`/api/rooms/:id/td`): база, 3 типа башен с улучшением, 4 типа врагов, маршрут, 4 этапа по узлам карты,
  серверная детерминированная симуляция, Team A/B с дуэлью, расходует Tomato Coins; см. docs/API.md.
* Помощь: «Бонус» (+25% XP к следующей сессии друга), «Щит» (10 монет, блокирует одну пакость).
  Пакости: «Туман», «Стикер» — только на перерыве, отключаемы, с кулдауном и лимитом, эффект не выходит
  за пределы перерыва.
* Достижения: 9 штук (см. `GET /api/config`).
