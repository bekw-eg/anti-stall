# Сценарий показа жюри

Показ идёт на демо-стенде: backend в демо-режиме раздаёт собранный frontend. Ведущий работает в браузере за
«живого» игрока, остальных игроков изображают песочные боты из терминала. Все 10 шагов идут строго по порядку из задания.

Что проверено на этапе 6 в браузере на таком стенде: шаги 1–5, 7 (прогресс 2/6 и 5/6), 8 (цель 6/6, «Цель достигнута»), 9 и
восстановление после перезагрузки. Шаг 6 (покупка улучшения через UI) в этой сессии вручную не проходился: покупки
закреплены автотестами и `cheat-check`; для него ниже есть запасной вариант.

## 1. Подготовка стенда

### 1.1. Запуск (за 5 минут до показа)

```bash
cd frontend && npm ci && npm run build
cd ../backend && npm ci
```

Запуск сервера из `backend/`. Отдельный файл БД нужен, чтобы показ начинался с чистых данных:

```bash
# bash / Git Bash
TOMATO_STATIC_DIR=../frontend/dist PORT=8799 TOMATO_DB=./data/demo-show.db node --disable-warning=ExperimentalWarning src/server.js --demo
```
```powershell
# PowerShell
$env:TOMATO_STATIC_DIR='..\frontend\dist'; $env:PORT='8799'; $env:TOMATO_DB='.\data\demo-show.db'; node --disable-warning=ExperimentalWarning src/server.js --demo
```

Без `TOMATO_DB` демо-сервер пишет в `backend/data/tomato-demo.db`. Файлы `data/*.db*` и `data/*.json` игнорируются git
(`backend/.gitignore`). В логе при старте должны быть строки `[tomato] db: …`, `[tomato] static: …` и предупреждение
`ДЕМО-РЕЖИМ ВКЛЮЧЁН`. Проверка: `curl http://localhost:8799/api/health` возвращает `"demoMode":true`.

### 1.2. Окна и терминалы

| Что | Где | Зачем |
|---|---|---|
| Браузер ведущего | http://localhost:8799 | «живой» игрок и хост комнаты |
| Терминал «Боты» | `backend/` | `npm run demo:bots`, команды через stdin |
| Терминал «Проверки» | `backend/` | `cheat-check`, при необходимости `curl` |
| Запасной браузер | окно инкогнито или другой профиль | второй «живой» игрок, если боты недоступны. У инкогнито свой `localStorage`, значит и свой аккаунт |

Тестовые данные. `npm run demo:seed -- --api http://localhost:8799` создаёт 4 песочных аккаунта (Лотти, Аня, Борис,
Вика) и отдельную демо-комнату «фокус 25 с / перерыв 15 с» с хостом Лотти. Токены, id и код комнаты сохраняются
в `backend/data/demo-seed.json` (файл в `.gitignore`). Эти аккаунты удобны для показа API через `curl`. Для показа
в интерфейсе они не нужны: интерфейс сам регистрирует песочный аккаунт. Без heartbeat-а аккаунты seed-а при старте
фокуса пропускаются как `offline` (скрипт сам об этом предупреждает).

### 1.3. Тайминги

| Параметр | Значение | Где задано |
|---|---|---|
| Фокус в демо-комнате из интерфейса | 25 с | `frontend/src/tomato/SettingsContent.tsx:64` (`focusSeconds: 25`), значение по умолчанию на сервере `backend/src/services/rooms.js:61` |
| Перерыв в демо-комнате | 15 с | `SettingsContent.tsx:64` (`breakSeconds: 15`), `rooms.js:62` |
| После перерыва | фаза «ожидание» без ограничения по времени: хост сам запускает следующий цикл | `rooms.js:327-332` |
| Кулдаун пакостей в демо-комнате | 1 с (в обычной 20 с) | `backend/src/config.js:87-88` |
| Пакостей за перерыв от одного отправителя | не больше 3 | `config.js:89` |

Один цикл занимает примерно 40 с плюс время до нажатия «Начать фокус».

### 1.4. Сколько циклов нужно до командной цели

> **Tower Wars (ветка `claude/tower-defense-rebuild-2eea3d`): правила карты изменились.** Фокус-сессии больше
> не двигают Road Map: награждённая сессия даёт команде +1 очко вклада (`focusPoints`) и те же монеты, что игроку,
> в казну команды (стартовый капитал казны — 30, `config.economy.treasuryStart`). Узел карты открывает только
> **победа в Tower Defense** на этапе текущего узла: «Лагерь» → «Лес знаний» → «Мост дедлайнов» → «Крепость экзамена»,
> победа на этапе крепости — командная цель. Прогресс карты `points` — число таких побед, цель `goal = 4`
> (`backend/src/catalog.js`, `ROADMAP`). Значит, до цели нужно минимум 4 выигранных раунда — по одному-два
> (с реваншем) за перерыв. Поражение ничего не отнимает: башни, уровни и узел сохраняются.
> Таблица ниже и шаги 7–8 описывают прежние правила (очки за сессии) и оставлены для истории.

Цель — 6 очков (`backend/src/catalog.js:52`, узел «Крепость экзамена»). Каждая **награждённая** сессия даёт команде
+1 очко (`backend/src/config.js:52`). Сессия досрочно вышедшего не засчитывается. Промежуточные этапы: «Лес знаний» — 2
очка, «Мост дедлайнов» — 4 очка (`catalog.js:50-51`).

| Игроков в комнате | Цикл 1 (один выходит досрочно) | Цикл 2 | Цикл 3 | Циклов до цели |
|---|---|---|---|---|
| 3 (ведущий + 2 бота) | 2 очка, «Лес знаний» | 5, «Мост дедлайнов» | 8 → цель | 3 |
| 4 (ведущий + 3 бота) | 3, «Лес знаний» | 7 → «Мост дедлайнов» и цель | — | 2 |

Вариант на 3 игрока совпадает с автотестом `backend/tests/team.test.js` «Тест 9: завершённые сессии двигают общий
прогресс; цель → командная награда один раз»: после первого цикла 2 очка, после второго 5, на третьем цель достигнута.
На этапе 6 в браузере вариант на 3 игрока доведён до 5/6. Вариант на 4 игрока посчитан по коду и в браузере не проверялся.

Основной план ниже рассчитан на 3 игрока: ведущий и боты «Гриша-бот» и «Даша-бот».
Для 4 игроков: `--bots 3`, третий бот — «Женя-бот», цель достигается на втором цикле.

### 1.5. Чем демо-режим безопасен (сказать жюри до или после шага 10)

- Режим включает только оператор сервера: флаг `--demo` или `TOMATO_DEMO=1` (`backend/src/config.js:9`). Клиент его не включает.
- Демо-комнаты (ускоренное время) доступны только **песочным** аккаунтам, а песочные аккаунты — только демо-комнатам.
  Проверка стоит при создании, входе по коду и по id, смене настроек и старте (`backend/src/services/rooms.js:48-52,81,107,172,258-259`).
  Обычный аккаунт получает `403 DEMO_SANDBOX_ONLY`, песочный в обычной комнате — `403 SANDBOX_DEMO_ONLY`.
- Токен песочного аккаунта не работает на сервере без демо-режима: REST отвечает 401, WS закрывается с кодом 4401 (`backend/src/services/users.js:36`).
- Демо-сервер по умолчанию пишет в отдельный файл БД `tomato-demo.db` (`config.js:15`). В Docker-compose у демо-стенда отдельный том `tomato-demo-data`.
- Повышенные потолки (500 сессий и 500 раундов TD в сутки) и кулдаун пакостей 1 с действуют только в комнатах с `room.demo`
  (`backend/src/services/game.js:81`, `td.js:172`, `social.js:99`). Обычные комнаты на демо-сервере работают по обычным правилам.
- Награда в демо-комнате считается как за стандартные 25 минут (`game.js:70-72`), но только для песочных аккаунтов.
- Проверено тестами `backend/tests/sandbox.test.js` (12) и `security.test.js` «изоляция песочницы: …», а также первыми четырьмя строками `cheat-check`.

## 2. Сценарий

### Шаг 1. Создание комнаты

**Ведущий:** открывает http://localhost:8799 → «Начать» → в панели «Настройки» вводит имя → показывает галочку
«Демо-режим»: она включена, заблокирована и подписана «Фокус 25 секунд, перерыв 15 секунд. Включён всегда: это
демо-песочница…» → «Создать комнату».

**Жюри видит:** комнату с названием и кодом из 6 символов, плашку «Демо-песочница», таймер 00:25, себя в ряду
участников, кнопки «Я готов» и «Начать фокус» (неактивна) и подсказку «Ждём участников — скопировать ссылку».

**Сказать:** «Комнату создаёт сервер и выдаёт код-приглашение. Это демо-сервер: здесь можно создать только ускоренную
песочную комнату, и прогресс из неё не попадает в настоящие аккаунты».

**Если сбой:** нет ответа сервера — Welcome показывает «Сервер недоступен — пробуем подключиться…». Проверить
`curl http://localhost:8799/api/health`, перезапустить сервер. Ошибка `DEMO_SANDBOX_ONLY` в тосте означает, что в браузере
остался обычный аккаунт; интерфейс сбрасывает такой токен при загрузке (`frontend/src/tomato/useTomato.ts:172-175`),
поэтому достаточно обновить страницу.

### Шаг 2. Подключение нескольких игроков

**Ведущий:** копирует код комнаты (в панели «Настройки» → «Скопировать ссылку» или из шапки) и в терминале «Боты» выполняет

```bash
npm run demo:bots -- --room КОД --bots 2 --api http://localhost:8799
```

**Жюри видит:** в терминале строки `[Гриша-бот] в комнате КОД, задача: «Химия: реакции»` и `[Даша-бот] …`.
В браузере в ряду участников появляются оба бота с зелёной отметкой «готов» и их задачами.

**Сказать:** «Каждый участник — отдельный аккаунт со своим токеном. Боты работают через тот же публичный API, что
и браузер: входят по коду, ставят задачу, держат присутствие через WebSocket и отмечают готовность».

**Если сбой:** боты пишут «работает НЕ в демо-режиме» — сервер запущен без `--demo`. Нет ботов — второй игрок заходит
из окна инкогнито по ссылке `http://localhost:8799/room/КОД`: ввести имя → «Войти в комнату» → «Я готов».

### Шаг 3. Запуск совместной учёбы

**Ведущий:** вводит свою задачу в поле «Над чем работаешь?» под таймером → «Я готов» → «Начать фокус» (кнопка
активна, когда готовы все участники в сети).

**Жюри видит:** у всех один отсчёт от 00:25. Статусы участников «в фокусе», у каждого своя задача. Игровых кнопок нет,
кнопка «Друзья» показывает «Сейчас все занимаются — помощь и шутки откроются на перерыве». Вместо «Начать фокус»
у ведущего кнопка «Завершить досрочно». В терминале ботов — `[комната] старт фокуса #1: участвуют 3, пропущены 0`.

**Сказать:** «Время хранит сервер: одна метка окончания фазы на всю комнату. Браузер только показывает оставшееся время.
Во время фокуса игровые действия закрыты и на сервере, и в интерфейсе».

**Если сбой:** кнопка «Начать фокус» неактивна и под ней «Ждём готовности всех участников в сети (x/y)» — кто-то не
нажал «Я готов». Боты отмечают готовность сами; во втором браузере нужно нажать «Я готов».

### Шаг 4. Досрочный выход одного участника

**Ведущий:** во время фокуса вводит в терминале «Боты»

```
leave Гриша
```

**Жюри видит:** в терминале `[Гриша-бот] досрочно вышел из фокуса — награды за эту сессию не будет` и
`[Гриша-бот] сессия без награды (aborted, user_abort)`. В браузере у Гриши статус «вышел раньше». Таймер у остальных идёт дальше.

**Сказать:** «Досрочный выход завершает только свою сессию. Комната продолжает работать, а сервер сразу помечает эту
сессию как прерванную и без награды».

**Если сбой:** команда пришла после конца фокуса — бот ответит отказом `NO_ACTIVE_SESSION` или `WRONG_PHASE`. Тогда
показать на следующем цикле. Без ботов: во втором браузере нажать «Завершить досрочно» и подтвердить «Точно? Награды не будет».

### Шаг 5. Начисление наград остальным

**Ведущий:** ждёт конца фокуса (25 с), затем открывает «Прогресс».

**Жюри видит:** экран темнеет (перерыв, таймер 00:15). Тосты у ведущего: «+100 XP · +20 монет · уровень 2»,
«Достижение: Первый фокус», «Достижение: Командный игрок», «Этап пройден: Лес знаний». В терминале:
`[Даша-бот] сессия завершена: +100 XP, +20 монет`, у Гриши начисления за эту сессию нет. В «Прогрессе» — уровень, XP,
монеты и вклад участников: у Гриши за этот цикл вклада нет.

**Сказать:** «Награду выдаёт только сервер, когда сам завершает фазу по своим часам. Маршрута "выдать награду"
у клиента нет. Награду получили только те, кто досидел до конца».

**Если сбой:** тосты пропущены (держатся 5 с, видно не больше трёх) — то же видно в «Прогрессе» и в «Настройки» →
«Профиль» → «История» (строки «завершена · +100 XP» и «досрочно · без награды»).

### Шаг 6. Улучшение игрового объекта

Объект развития — база и башни команды в мини-игре Tower Defense. Улучшения игрока усиливают её на сервере
(`backend/src/services/td.js:33-51`).

**Ведущий:** на перерыве или после него, в фазе ожидания (покупка запрещена только во время своей сессии,
`backend/src/services/game.js:275-277`): «Настройки» → вкладка «Профиль» → «Улучшения» → у «Крепкие стены» нажать
«30 монет». Затем «Свернуть». На следующем перерыве открыть «Игра».

**Жюри видит:** уровень улучшения 1/5, баланс уменьшился на 30 и вырос на 15 за достижение «Прокачка». После первого
цикла у ведущего 55 монет (20 за сессию, 10 за «Первый фокус», 15 за «Командный игрок», 10 за этап), после покупки — 40.
В «Игре» подпись «Базу укрепляют «Крепкие стены» (сейчас 125 HP)» (база 100 + 25 за уровень, `backend/src/catalog.js:14`).

**Сказать:** «Монеты зарабатываются только учёбой и тратятся на улучшения. Цену и уровень проверяет сервер, а эффект
улучшения влияет на мини-игру: у базы больше здоровья».

**Если сбой:** покупка через интерфейс в этой сессии не проверялась. Запасной вариант на перерыве: «Игра» → клик по
свободному месту → «Лучник» (15 монет) → клик по башне → «Улучшить · 12 монет»
(цена `round(15 × 0,8)`, `catalog.js:87`). Если интерфейс недоступен, показать строку `cheat-check`
«Повтор покупки улучшения (тот же expectedLevel), price:-1000 в теле» → «цена 30, повтор STALE_LEVEL».

### Шаг 7. Продвижение Road Map

> **Tower Wars:** на перерыве игра открывается сама. Постройте 1–2 башни из казны команды (её баланс виден в игре и на
> карте), запустите раунд этапа «Лагерь» и дождитесь победы — маркер переедет на «Лес знаний», прогресс 1/4, тост
> «Этап пройден: Лес знаний». Фокус-сессии карту не двигают, а пополняют казну и очки вклада (на карте — «Очки вклада» и
> «Казна»). Ниже — прежний сценарий.

**Ведущий:** нажимает «Карта» в шапке (или полоску цели в нижней панели). Затем закрывает карту («Таймер»),
нажимает «Я готов» → «Начать фокус» (боты отмечают готовность сами) и проводит второй цикл целиком.

**Жюри видит:** на карте «Марш к крепости экзамена» маркер команды стоит на «Лес знаний», прогресс 2/6, следующий этап
«Мост дедлайнов», блок «Вклад». После второго цикла маркер переезжает, прогресс 5/6, тост «Этап пройден: Мост
дедлайнов», в терминале `[комната] команда дошла до «Мост дедлайнов»`.

**Сказать:** «Каждая завершённая сессия — одно очко команды. Этапы и награды за них фиксирует сервер ровно один раз.
Гриша вышел в первом цикле, поэтому тогда засчитано два очка из трёх возможных».

**Если сбой:** карта не открылась — тот же прогресс видно в нижней полосе («Командная цель … 2/6») и в «Прогрессе»
(«Командный прогресс»).

### Шаг 8. Достижение командной цели

> **Tower Wars:** цель — победа на этапе «Крепость экзамена» (4/4). Ниже — прежний сценарий.

**Ведущий:** проводит третий цикл («Я готов» → «Начать фокус»), ждёт конца фокуса.

**Жюри видит:** тост «Команда достигла цели», начисление +150 XP · +60 монет, достижение «Коллективная победа».
В терминале `[комната] командное испытание пройдено!` и у ботов `награда team_challenge: +150 XP, +60 монет`.
На карте маркер на «Крепость экзамена», 6/6 (очков может быть больше, цель засчитана).

**Сказать:** «Командную награду получает каждый, кто внёс вклад, и только один раз. Это закреплено уникальным ключом
в журнале наград, поэтому повторить её нельзя».

**Если сбой:** поведение закреплено тестом
`backend/tests/team.test.js` «Тест 9: …» и `roadmap.test.js` «финальный узел выдаёт командную награду…». Если не хватило
очков (например, кто-то был offline и пропущен), провести ещё один цикл.

### Шаг 9. Помощь и пакость

Делается на перерыве после цели. Перерыв длится 15 с, поэтому обе команды лучше набрать заранее и отправить сразу.

**Ведущий:** в терминале «Боты» (ИМЯ — имя ведущего в комнате, регистр не важен, можно начало имени):

```
help ИМЯ boost
prank ИМЯ fog
```

Затем сам открывает «Друзья» и отправляет боту «Бонус к XP» или «Стикер».

**Жюри видит:** тост «Вам помогли: бонус к XP в следующей сессии». Затем экран затягивает туман с подписью
«Туман от …-бот · N с» и кнопкой «Убрать». В ленте «Друзья» у всех появляются записи. В «Друзья» видны правила:
«Бонус: +25% XP за следующую сессию друга. Щит отражает одну шутку. Шутки … заканчиваются вместе с перерывом
и не трогают ни таймер, ни награды».

**Сказать:** «Помощь даёт реальный игровой эффект: +25% XP к следующей сессии. Пакость только визуальная, исчезает с
концом перерыва и не влияет на учёбу. Получение пакостей можно отключить, тогда отправлять их тоже нельзя».

**Если сбой:** бот ответил `WRONG_PHASE` — перерыв закончился. Провести ещё один цикл и повторить на следующем
перерыве. `ALREADY_SENT` — этот тип этому игроку в этот перерыв уже отправлялся; скрипт сам пробует другого бота и
другой тип. Пакость не прошла с `PRANKS_DISABLED` — у получателя выключены шутки («Друзья» → «Получать шуточные эффекты»).

### Шаг 10. Демонстрация защиты от читов

**Ведущий:** в терминале «Проверки»

```bash
npm run cheat-check -- --api http://localhost:8799
```

Скрипт работает около 7 с: создаёт свои песочные аккаунты и демо-комнаты с фокусом 5 с, выполняет 24 атаки и печатает
таблицу «Атака | Ожидание | Факт | Итог». Код выхода 1, если хоть одна атака прошла.

По желанию жюри — ручная проверка через `curl` (вместо ТОКЕН — токен из `backend/data/demo-seed.json` или из ответа регистрации):

```bash
# подмена баланса в профиле игнорируется: в ответе xp и coins не меняются
curl -s -X PATCH http://localhost:8799/api/users/me -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"xp":99999,"coins":99999,"level":50}'
# маршрута «выдать награду» нет: 404 NOT_FOUND
curl -s -X POST http://localhost:8799/api/users/me/reward -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"xp":100}'
# цена из тела запроса не используется: при нулевом балансе 409 INSUFFICIENT_FUNDS, required 30
curl -s -X POST http://localhost:8799/api/users/me/upgrades/base_walls/purchase -H "Authorization: Bearer ТОКЕН" -H "Content-Type: application/json" -d '{"price":0}'
```

Эти три запроса выполнены на этапе 6 против стенда на 8799, ответы совпали с описанными.

**Жюри видит:** таблицу из 24 строк, все PASS, в конце «PASS: все 24 атак отражены». Полный вывод последнего
прогона — в [SECURITY_QA.md](SECURITY_QA.md).

**Сказать:** «Скрипт атакует живой сервер теми же HTTP- и WebSocket-запросами, которые может отправить любой клиент:
повторы, подмена полей, параллельные покупки, вторая сессия, чужая комната, обход песочницы. Те же атаки детерминированно
проверяет `tests/security.test.js`».

**Если сбой:** скрипт сообщает, что сервер не в демо-режиме, — нужен `--demo`. Запасной вариант без живого сервера:
`node --disable-warning=ExperimentalWarning --test tests/security.test.js tests/sandbox.test.js` (23 теста, около 1,5 с).
