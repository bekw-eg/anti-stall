# Архитектура AntiStall

## Компоненты

```
 Браузер (React + Vite)                         ВМ (Docker Compose)
 ┌──────────────────────┐   HTTPS / WSS    ┌────────────────────────────────────────────┐
 │ экраны, Canvas игр   │ ───────────────► │ Caddy :443 / :8081  — TLS (Let's Encrypt),  │
 │ таймер = серверное   │                  │   редирект :80 → https, gzip/zstd           │
 │ время + смещение     │                  │      │                     │                │
 └─────────┬────────────┘                  │      ▼                     ▼                │
           │ WebRTC (голос, p2p)           │  app (Node 22)        demo (Node 22,        │
           ▼                               │  REST /api + WS /ws   TOMATO_DEMO=1)        │
   другой браузер ◄── STUN / TURN          │  SQLite WAL           своя SQLite           │
                                           │  том tomato-data      том tomato-demo-data  │
                                           └────────────────────────────────────────────┘
```

- **Один образ** (`Dockerfile`): Node раздаёт собранный фронтенд, REST `/api` и WebSocket `/ws`. Два стенда из одного образа: основной и демо для жюри (ускоренное время, песочные аккаунты, отдельная БД).
- **Сервер решает всё**: таймер фаз (`rooms.js`, тик 500 мс, фазы догоняются из БД после рестарта), награды (`game.js`, журнал `reward_transactions` с `UNIQUE(user_id, key)` — повтор запроса не начисляет дважды), игры (`td.js`, `harvest.js` — детерминированные симуляции, клиент присылает только действия). Клиент показывает.
- **Синхронизация**: на каждое изменение сервер шлёт событие в WS комнаты; клиент перечитывает снимок. Без ручного обновления страницы.
- **Почему SQLite**: одна ВМ, один процесс на стенд, транзакции и WAL — достаточно для MVP; встроен в Node 22 (`node:sqlite`), без отдельного сервиса. Предел — горизонтальное масштабирование (см. риски).

## Оценка работы и командный бонус

После фокуса игрок ставит ★1–5 (`POST /api/rooms/:id/session/rating`, `focus_sessions.rating`, миграция v10): один раз,
только за свою завершённую сессию и только до начала следующего фокуса. В конце перерыва (`rooms.endBreak`, а также при
закрытии комнаты на перерыве) `game.ratingBonus` начисляет каждому награждённому участнику бонус = награда за фокус ×
(средняя оценка его команды / 5) × `economy.ratingBonusShare` (0,5); не ответившие считаются как 3★. Ключ журнала
`rating:<cycleId>:<userId>` не даёт начислить бонус дважды, а так как база — уже начисленная награда, суточный лимит и
качество присутствия учтены сами. Оценка влияет только на бонус и усредняется по команде, клиент ничего не считает.

## Путь в продакшен

MR → CI `test` (backend `node --test`, проверка новой БД `db-check`, frontend `tsc` + `vitest`; красные тесты останавливают пайплайн) → `build:image` (Kaniko, образ с тегом SHA в registry Spirit) → только master: `setup:vm` → `deploy:vm` по SSH:
1. бэкап БД обоих стендов (`db-backup.js`, 5 последних снимков);
2. `docker compose pull` + `up` (миграции выполняются при старте);
3. проверка `/api/health` изнутри и сертификата снаружи; HTTPS не поднялся — откат на HTTP, стенд не пропадает;
4. `db-check` на обеих БД;
5. запись `current_image` / `previous_image`.

Откат — ручная джоба `rollback:vm` (предыдущий образ тем же путём). Подробно — `docs/DEPLOY.md`.

## Конфигурация

Все настройки — переменные окружения (таблица в `docs/DEPLOY.md`), проверяются при старте (`checkEnv`): неверное значение — сервер не стартует и пишет причину. Экономика и тайминги — `backend/src/config.js` (в коде, под тестами). Секреты (SSH-ключ, ключ registry) — только в CI-переменных Spirit.

## Интеграции

| С чем | Зачем | Если сломалось |
|---|---|---|
| Let's Encrypt (через Caddy) | сертификат: голос в браузере работает только по HTTPS | `deploy.sh` откатывается на HTTP — всё, кроме голоса, работает |
| Registry Spirit | хранение образов | деплой не скачает новый образ → остаётся текущий |
| GitLab CI / Spirit | сборка и доставка | стенд продолжает работать на текущем образе |
| STUN (Google, Cloudflare) / TURN | соединение голоса между браузерами | без TURN через строгий NAT (мобильный интернет) голос может не соединиться; остальное не зависит |

## Сбои и как переживаем

| Что | Что происходит |
|---|---|
| Процесс упал / необработанная ошибка | лог `uncaughtException`, выход; Docker (`restart: unless-stopped`) поднимает заново; фазы комнат догоняются из БД, участникам даётся свежий grace-период |
| Обновление (SIGTERM) | закрываются WS и БД, затем выход; таймер на сервере продолжится после старта |
| Обрыв связи у игрока | клиент переподключается; внутри grace-периода (30 с) сессия фокуса не теряется |
| Повтор / гонка запросов | транзакции + уникальные ключи журнала наград: двойного начисления нет (проверяет `db-check`) |
| Ошибка миграции | транзакция откатывается, сервер не стартует, health красный — видно в деплое; откат образа |
| Испорченные данные | восстановление из `/data/backups` (`docs/DEPLOY.md`) |

## Риски и что с ними делать

- **Одна ВМ, SQLite** — нет горизонтального масштабирования. Для роста: вынести хранилище в Postgres, состояние комнат — в общий брокер событий; код сервисов уже отделён от транспорта.
- **Голос без TURN** — см. интеграции; решение — coturn на ВМ или внешний TURN (переменные уже поддерживаются).
- **Демо-режим** — ускоренное время только для песочных аккаунтов и отдельной БД; без флага сервера их токены не работают.
