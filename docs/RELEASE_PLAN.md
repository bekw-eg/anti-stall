# AntiStall — план до сдачи (15.11)

Этот файл — общий план для троих. Любой может продолжить с любого места: этапы самодостаточны, у каждого есть ветка, файлы, критерий готовности и проверка.
Источники: кейс `Tomato.pdf` (§5, §10), `Критерии.pdf` (жюри Backend / Frontend / Продакт + штрафы), хэнд-тест 15.11, комментарий ментора, артефакт «AntiStall перед защитой».

## Как работаем (обязательно)
1. Перед этапом: `git switch master && git pull`, ветка **от свежего master**: `release/<этап>-<кратко>` (например `release/2-metrics`).
2. Взял этап — впиши своё имя в колонку «Кто» здесь и запушь (чтобы двое не делали одно и то же).
3. Один этап = один MR в master. **Ветки после слияния не удаляем** (снять галочку «Delete source branch»).
4. В том же MR отметь `[x]` у сделанного в этом файле.
5. Тесты backend — только нужный файл: `cd backend && node --test --test-reporter=tap tests/<файл>.test.js | grep -E "^# (pass|fail)|not ok"`. Frontend: `npx tsc --noEmit -p tsconfig.app.json && npx vitest run`.
6. После слияния: дождаться деплоя (~3 мин) → `curl https://<домен>/api/health` → пройти изменённое на демо `:8081`.
7. Tower Defense / Harvest меняет автор игр или по согласованию с ним.

**Effort** (сложность, она же уровень усилий ассистента): `low` — правка в 1–2 местах, < 1 ч · `medium` — несколько файлов, 1–3 ч · `high` — новая подсистема, полдня · `xhigh` — несколько подсистем / тонкая логика, день · `max` — рискованная переделка ядра · `ultracode` — большой объём, параллельные агенты. Задач уровня max/ultracode в плане нет.
