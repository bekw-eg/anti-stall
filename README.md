# Аксолотль Лаб — игра-кликер и автодеплой через GitLab CI

Интерактивная игра-кликер про аксолотля (Vite + React + shadcn/ui), которая по `git push` в `master`:

1. **собирается** в Docker-образ (Kaniko) и публикуется в Spirit Registry;
2. **деплоится** на вашу виртуальную машину по SSH и запускается через `docker compose`.

```
push в master ─► build:image ─► setup:vm ─► deploy:vm ─► http://<ВМ>:80
                 (registry)                 (ssh + docker compose)
```

В merge request выполняется только `build:image`, деплой идёт только из `master`.

## Что нужно один раз настроить

### 1. Виртуальная машина
- Установлены Docker и плагин `docker compose`.
- Пользователь по умолчанию `root`. Если используете другого, он должен уметь `sudo` без пароля. В пайплайне `dp` и `docker` запускаются через `sudo`, поэтому `sudo` должен быть установлен и у `root`.
- Порт приложения (по умолчанию `80`) открыт и не занят другим контейнером.

### 2. SSH-ключ
Есть два варианта, выберите один:

**а) Получить в интерфейсе VMaaS.** При заказе ВМ в VMaaS Spirit выдаёт SSH-ключ. Содержимое выданного **приватного** ключа пойдёт в `DEPLOY_KEY`.

**б) Сгенерировать самому:**
```bash
ssh-keygen -t ed25519 -f deploy_key -N ""
ssh-copy-id -i deploy_key.pub <пользователь>@<адрес-ВМ>   # публичный ключ → на ВМ
```
Содержимое **приватного** `deploy_key` пойдёт в переменную `DEPLOY_KEY`.

В любом случае не коммитьте приватный ключ в репозиторий!

### 3. Сервис-аккаунт Spirit
Нужен, чтобы CI мог публиковать образ, а ВМ — скачивать его.

Сервис-аккаунт и CI-переменная `SPIRIT_DOCKER_SA_KEY` **должны быть созданы заранее** (создавать сервис-аккаунты и выдавать им роли может только Project lead тенанта). Добавлять их самим не нужно, пайплайн просто их использует.

> Если сборка или деплой падают с ошибками авторизации в registry (401/403) или не находят `SPIRIT_DOCKER_SA_KEY`, обратитесь к тем, у кого в тенанте есть роль **Project lead**.

### 4. Переменные CI/CD
Репозиторий в Spirit → **Код → Репозитории** → нужный репозиторий → вкладка **CI-переменные** → **Добавить переменную**.
(Создавать их может роль **Project lead** или **Repository CI variables**.)

| Ключ | Тип | Значение |
|---|---|---|
| `SPIRIT_DOCKER_SA_KEY` | **Файл** | содержимое `key.json` сервис-аккаунта. **Создаётся заранее Project lead'ом, самим добавлять не нужно** |
| `DEPLOY_KEY` | **Файл** | содержимое приватного SSH-ключа (с переводом строки в конце!) |
| `DEPLOY_HOST` | Переменная | публичный адрес ВМ (или впишите в `variables:` в `.gitlab-ci.yml`) |
| `DEPLOY_USER` *(необязательно)* | Переменная | пользователь на ВМ, по умолчанию `root` |
| `APP_PORT` *(необязательно)* | Переменная | порт на ВМ, по умолчанию `80` |

**Что кого перекрывает.** Переменная репозитория **приоритетнее** значения из `variables:` в `.gitlab-ci.yml`.
Поэтому `DEPLOY_HOST` и `DEPLOY_USER` можно либо вписать прямо в файл, либо задать в Spirit: в Spirit побеждает.

Замечания:
- Файловые переменные нельзя замаскировать, поэтому включайте **Защищённая**: тогда они доступны только в защищённых ветках (`master`).
- «Маскировать» работает только для значений от 8 символов из Base64-алфавита (и `@`, `:`), для `root` или IP с точками оно не подойдёт.
- Если в значении есть `$`, экранируйте как `$$`.
- **Environment scope** ограничивает переменную окружением (например, `production`). Оставляйте `*`.

Подробнее: [переменные CI/CD](https://docs.pages.spirit.t-education.com/docs/docs/build/ci-variables).

## Запуск
Сделайте коммит в `master`, откроется пайплайн. После успешного `deploy:vm` приложение доступно на `http://<адрес-ВМ>:80/`.

Локально:
```bash
npm ci
npm run dev       # dev-сервер, порт 4499
npm run build     # сборка для продакшена
```

## Как работает вход в Docker Registry
Registry Spirit пускает только по токену, а получить его можно через **Spirit CLI (`dp`)** и ключ сервис-аккаунта:
```bash
dp auth service-acc --key-file key.json   # логин сервис-аккаунтом
dp auth configure-docker                  # пишет ~/.docker/config.json, токен подставляется сам
```
Поэтому везде, где нужен доступ к registry, нужны **`dp` и ключ SA**:
- **сборка**: шаблон `.dp_build` (образ `base-kaniko` уже содержит `dp`) сам делает вход по `SPIRIT_DOCKER_SA_KEY`;
- **деплой**: джоба `deploy:vm` запускается в образе `DEPLOY_IMG` (по умолчанию `cicd-images/base-noble`). Перед ней `setup:vm` ставит на ВМ `dp`, если его нет. Затем `deploy:vm` копирует ключ на ВМ и по SSH выполняет там `dp auth service-acc` + `dp auth configure-docker`, после чего `docker compose pull` проходит авторизацию.

Токен живёт 1 час, но `configure-docker` обновляет его автоматически, пока действителен ключ SA. Истёк ключ: создайте новый и обновите переменную.

## Как это устроено
| Файл | Роль |
|---|---|
| `.gitlab-ci.yml` | пайплайн: `build:image` → `setup:vm` → `deploy:vm` (деплой: несколько команд `ssh`/`scp` прямо в джобе) |
| `Dockerfile` | как собрать образ (`npm ci`, `npm run build`, `vite preview` на порту 3000) |
| `deploy/docker-compose.yml` | как запустить образ на ВМ (`APP_PORT` → порт 3000 контейнера) |

Сборка использует шаблон `.dp_build` из `pipelines/pipelines`. Образ публикуется как
`registry.spirit.t-education.com/<тенант>/<репозиторий>:<короткий sha коммита>`.

## Частые ошибки
| Симптом | Причина |
|---|---|
| `build:image`: `Pushing image to /<тенант>/...` (пустой хост) и 401 от `index.docker.io` | не задана `DOCKER_ARTIFACTORY_REGISTRY`, она должна быть `registry.spirit.t-education.com` (задана в `.gitlab-ci.yml`) |
| `build:image`: 401/403 от registry | неверный или просроченный ключ в `SPIRIT_DOCKER_SA_KEY` или у сервис-аккаунта нет роли: обратитесь к Project lead тенанта |
| `build:image`: `npm ci` падает | `package.json` и `package-lock.json` рассинхронизированы; в репозитории также лежит `bun.lockb` |
| `Permission denied (publickey)` | публичный ключ не на ВМ, или в `DEPLOY_KEY` не тот ключ |
| `error in libcrypto` | у файла-ключа нет перевода строки в конце |
| `docker pull` на ВМ: unauthorized | не отработал `dp auth ...`, ключ сервис-аккаунта истёк |
| `ssh: command not found` / `apt-get` без прав | в образе `DEPLOY_IMG` нет `ssh` и нет root; возьмите образ с `openssh-client` |
| `cannot save helper script ... permission denied` | `dp`/`docker` на ВМ запущены без `sudo` (в шаблоне они запускаются через `sudo`) |
| `setup:vm` падает на `sudo` | на ВМ нет `sudo` или он требует пароль; поставьте `sudo` или `dp` на ВМ вручную ([инструкция](https://docs.pages.spirit.t-education.com/docs/docs/build/registry)) |
| `port is already allocated` | порт 80 занят другим контейнером на ВМ (например, от старого деплоя); остановите его или задайте `APP_PORT` |
| деплой прошёл, но сайт не открывается | порт закрыт на ВМ/в фаерволе |
